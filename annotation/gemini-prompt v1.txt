Annotation Rules:

1. Vulnerability Spans: Identify the exact text string representing the vulnerability or risk. Apply the closest matching taxonomy label. Apply multiple labels to a single span if it implies more than one vulnerability.

2. Entity Spans: Tag every span that a vulnerability could be linked to. There are three entity types:
   - `Person_Name`: a proper name identifying a person e.g. "James", "Mrs Ahmed", "[Person1]"
   - `Person_Role`: a descriptive role or relational label e.g. "tenant", "his mother", "the children"
   - `Person_Pronoun`: a pronoun that is the primary reference to a person in the absence of a nearby name or role e.g. "she" in "she has asthma" where no name or role has been recently established

   Do not tag every pronoun — only tag a pronoun when it is doing the work of identifying who a vulnerability belongs to and there is no name or role span nearby to link to instead.
   When a person has both a name and a role mentioned nearby, prefer linking to the name span.

3. Entity Linking: Link each vulnerability span to the entity span it belongs to using a `Vulnerability -> Entity` relationship. If a vulnerability span cannot be linked to any entity (the person is unidentifiable from context), leave it unlinked.

4. Disambiguation: If multiple people are mentioned, ensure each vulnerability is linked to the correct person. For example, if the note mentions a tenant and her daughter, link breathing problems to the daughter if the text specifies it is her condition.
