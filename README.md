# CS3D6 – Additional Needs Extraction

This repository contains the source code and synthetic datasets for the CS3D6 project investigating automatic extraction of **Additional Needs** from housing case notes.

The project applies Natural Language Processing (NLP) to identify references to additional needs (e.g. physical health, mental health, safeguarding concerns) within free-text housing records and, where possible, determine which household member each need refers to.

The system is implemented as a three-stage pipeline:

1. **Span extraction (NER)**, which identifies Additional Needs and person references within a case note.
2. **Relation extraction**, which links each identified need to the corresponding person reference.
3. **Entity linking**, which applies rule-based matching to resolve extracted needs to household member IDs.

The repository also includes preprocessing scripts, evaluation utilities, and a lightweight visualiser for comparing model predictions against the ground truth.

## Notes for Examiners

All data provided with this repository is synthetic (generated by Google Gemini), to comply with Data Protection requirements.

Some scripts interact with AWS services used during development (e.g. AWS Athena, SageMaker and Comprehend). These are retained for completeness but cannot be executed without the appropriate AWS credentials.

The remaining machine learning and evaluation components can be run locally or using the DCS Batch Compute resources.

## Repository Structure

This is a **monorepo**. Each package owns its own `pyproject.toml` and `requirements.txt` — there is no root Python package.

- `dev/` — training, preprocessing, evaluation, and experimentation
- `inference/` — production batch inference container (SageMaker / Airflow)

```text
.
├── data/                         Datasets, models, logs, and evaluation outputs
├── docs/                         Supporting documentation
├── inference/                    Production inference container
│   ├── src/                      Runtime package (models, linker, schemas, entrypoint)
│   ├── tests/                    Fast unit tests (pytest)
│   ├── Dockerfile
│   ├── pyproject.toml
│   └── requirements.txt
├── dev/                          Training and evaluation
│   ├── common/                   Shared utilities (paths, logging, JSON helpers)
│   ├── preprocessing/            Preprocessing scripts and notebooks
│   ├── spans/                    Span extraction training and evaluation
│   ├── relations/                Relation extraction training and evaluation
│   ├── entity_linking/           Experimental entity linking scripts
│   ├── shared/                   Shared model implementations and evaluators
│   ├── pyproject.toml
│   ├── requirements.txt
│   └── launch_sagemaker.py       SageMaker training job launcher *(requires AWS)*
├── visualizer/                   React application for visualising predictions
└── .github/workflows/            CI (inference tests only)
```

Install and run each package from **inside that directory**.

## Installation

The project uses **Python 3.12**.

### Training / evaluation (`dev/`)

```bash
python -m venv .venv
source .venv/bin/activate

cd dev
pip install -e .
pip install -r requirements.txt
```

### Production inference (`inference/`)

```bash
cd inference
pip install -e .
pip install -r requirements-dev.txt   # runtime + pytest
```

The visualiser component uses React and Javascript. This requires **Node v24+**.

Installation:
```bash
cd visualizer

npm install
```

### GPU Support

The experiments reported in the report were trained using AWS Sagemaker GPU instances (`ml.g5.xlarge`). This has a NVIDIA A10G GPU, 24 GBs of VRAM, and 4 vCPUs (see [docs](https://aws.amazon.com/ec2/instance-types/g5/)).

Training can also be performed on a local machine with a compatible GPU. Please ensure it has sufficient VRAM.

The remaining components, including data preprocessing, inference, evaluation, and the visualiser, can be run on a CPU-only machine.

Refer to the official [PyTorch installation guide](https://pytorch.org/get-started/locally/) for installation instructions for your platform.

See the DCS Batch Compute System guide: https://warwick.ac.uk/fac/sci/dcs/intranet/user_guide/batch_compute/

## Running / Reproducing Experiments

### Data Preprocessing

The preprocessing pipeline prepares the housing dataset for annotation, training, and evaluation.

The main preprocessing components are:

| File | Purpose | Runs on DCS? |
|---|---|---|
| `1_construct_taxonomy.py` | Constructs the Additional Needs taxonomy from the source CSV and adds associated regex patterns. | ✅ |
| `2_create_gold_standard_dataset.ipynb` | Samples and prepares the gold standard dataset from AWS Athena data. Performs acronym expansion, regex-based weak labelling, exploratory analysis, stratified sampling, PII redaction, pre-annotation, and export. | ✅<br>*(Athena call replaced with CSV)*|
| `3_generate_label_studio_ui.py` | Generates a Label Studio annotation interface from the taxonomy. | ✅ |
| `4_convert_gemini_predictions.py` | Converts Gemini predictions into Label Studio-compatible annotation spans. | ❌ <br>*Gemini pre-annotations not provided for synthetic data* |
| `5_process_annotations.ipynb` | Exploratory analyis; Converts Label Studio annotations into the standard format used for model training and evaluation. Merges rare labels. | ✅ |
| `6_add_household_to_gs.py` | Adds pseudonymised household member information required for entity attribution experiments back to Gold Standard. | ❌ <br>*Not needed. Provided with synthetic data.* |
| `7_create_splits.py` | Creates train, validation, and test splits using multi-label stratification and duplicate-leakage prevention. | ✅ |
| `8_prep_comprehend_data.py` | Converts data into the format required by AWS Comprehend custom entity recognition. | ✅❌ <br>*Functional, but irrelevant – Comprehend outputs not provided for synthetic data.* |
| `fake/*` | Scripts for generating fake data | ✅❌ <br>*Functional, but irrelevant* |

The repository also contains `docs/reshaping_script/`, which contains the SQL and Python scripts originally used to collect and filter MMH notes data in Hackney's AWS data platform.

These scripts:
- execute an AWS Athena query to ingest and reshape notes data;
- join notes with tenancy information;
- apply data quality and business logic flags;
- write the resulting dataset to S3 as Parquet and register it in AWS Glue.

They are included for documentation and reproducibility context only. They are **not functional** outside the original AWS environment and require access to Hackney's internal data infrastructure.

### Training

Commands in this section are run from `dev/` after installing that package.

The project contains implementations of the transformer-based models evaluated in the dissertation:

- span classification for Additional Needs entity extraction;
- relation classification for linking extracted needs to household members.

Training scripts are located under:

```bash
python spans/training/train_span.py
python relations/training/relation_extraction.py
```

Training configuration is defined using dataclasses at the top of each training script.

The span model also includes a separate threshold sweep script:
```bash
python spans/training/optimize_thresholds.py <path/to/final_model>
```

Training is computationally expensive and GPU acceleration is recommended.

## Evaluation

Evaluation scripts generate model predictions and compare them against the annotated test set.

Evaluation is split into two stages:

1. **Prediction generation**  
   Each extraction approach produces predictions in a standard format.

2. **Evaluation and comparison**  
   Predictions are compared against the ground truth annotations using the evaluation metrics described in the report.

#### Span Extraction Evaluation

Prediction scripts are located under:
```bash
python spans/eval/predict_*.py [<data/results/predicted/file>]
```
These scripts generate predictions for the different approaches evaluated in the dissertation, including:

- regex-based baseline;
- transformer span classifier;
- AWS Comprehend; (not available for synthesised data)
- gemini pre-annotations; (not available for synthesised data)

`compare_eval_spans.py` loads the generated predictions and evaluates all configured approaches against the test set and presents tables.

#### Relation Extraction Evaluation

Relation evaluation is located under:
```bash
python relations/eval/predict_*.py
```
The relation evaluation scripts support evaluating entity attribution using either:

- gold-standard entity spans;
- predicted entity spans generated by an extraction model.

Using predicted spans helps measure cascading errors.

`compare_eval_relations.py` loads the generated predictions and evaluates all configured approaches against the test set and presents tables.

Evaluation does not require GPU acceleration (the span model takes ~5 minutes on CPU; the relation model ~10 minutes). 

#### Entity Linking
Production entity linking lives in `inference/src/models/entity_linker.py` (deterministic heuristics, no model weights).

The evaluation script that writes CSV for the visualiser is:
```bash
python entity_linking/match_needs_to_persons.py
```
It is not quantitatively evaluated due to a lack of annotated ground truth data. Results can be manually inspected using the visualiser (See below).

## Visualiser

The repository includes a Vite/React visualisation application for manually analysing model predictions.

The visualiser displays ground truth annotations alongside predictions and the entity linking results. It requires prediction outputs generated by the evaluation pipeline.

To run the application:

```bash
cd visualiser

npm install

npm run dev
```

Before starting the application, copy the required output files into:

```bash
visualiser/public/data/
```

The filenames used by the application are configured in:
```bash
visualiser/src/config.js
```
